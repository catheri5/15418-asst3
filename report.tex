\section{Implementation Status}

We first implemented a sequential correctness baseline before adding OpenMP
parallelism.  The starter code's compressed route representation was replaced
with a keypoint representation: each wire stores up to five points, corresponding
to the start point, up to three bends, and the end point.  This matches the
assignment checker format and makes route construction and validation easier to
reason about.

At the start of timed computation, each input wire is assigned a simple legal route.  If the
endpoints share a row or column, the initial route is straight.  Otherwise, the
initial route is a horizontal-first one-bend path.  The occupancy matrix is then
constructed by adding each initial wire route.

The sequential correctness baseline visits every wire for each iteration.
For a wire being reconsidered, the current route is first removed from the
occupancy matrix.  With fixed probability $P$, the program chooses a legal route
uniformly at random.  Otherwise, it evaluates every legal route with at most
three bends using the sum of squared occupancy values that would result from
adding the wire back, and chooses the lowest-cost route.  The existing route is
preserved unless a strictly cheaper candidate is found.  The selected route is
then added back into the occupancy matrix.

\section{Route Generation and Cost Calculation}

For non-collinear endpoints, route generation currently includes horizontal-first
and vertical-first routes with at most two bends, plus exactly three-bend routes
through each strictly interior point in the endpoint bounding box.  Choosing
strictly interior points for the three-bend case prevents those routes from
collapsing into duplicate one- or two-bend routes.  Some at-most-two-bend routes
do collapse to one-bend routes; consecutive duplicate keypoints are removed when
constructing the wire.

Within-wires scoring removes the current wire before evaluating its candidates.
Therefore each occupied cell on a W-mode candidate is scored using
$(occupancy[y][x] + 1)^2$. Across-wires cannot generally remove the current
wire during selection: another worker may be reading that occupancy cell while
the current batch is still being scored. A-mode instead leaves the old route in
the matrices, recognizes where a candidate overlaps it, and scores an
overlapping cell as $occupancy[y][x]^2$ because the old wire's removal and the
candidate's insertion cancel. Non-overlapping cells still use
$(occupancy[y][x] + 1)^2$. Section~\ref{sec:final-decisions} describes the
resulting synchronization and geometry decisions in more detail.

route. This removes candidate-vector allocation, growth, and storage overhead
without changing the exhaustive route set. The random branch constructs just
the uniformly selected route without building the candidate list.

We also specialized the cost loop for horizontal and vertical segments.
Horizontal scoring fixes a row and changes only the column index; vertical
scoring fixes a column and changes only the row index. Initially, vertical
access still crossed separately allocated rows. We subsequently added a
transposed raw occupancy view, \texttt{occupancy\_columns[x][y]}, alongside
\texttt{occupancy[y][x]}. Horizontal segments now read contiguous rows and
vertical segments read contiguous columns. Every wire removal and insertion
updates both views. This trades additional memory and update work for better
locality during the many candidate-scoring reads.

The transposed view is not a prefix-sum table or a cache of route costs.
Every candidate is still evaluated completely, without cost reuse or early
termination, and bends and the final endpoint are counted exactly once.
The optimized traversal is now used by both modes. Both use indexed generation:
A generates candidates sequentially within a batch, while W distributes
candidate generation and scoring across threads as described below.

\section{Within-Wires Parallelism}

We keep iterations and the outer loop over wires sequential. After removing
the current wire from both occupancy views, all candidates for that wire can
be evaluated independently against the same read-only occupancy state. The
chosen route is committed before moving to the next wire.

Our initial parallel implementation generated a candidate vector sequentially
and parallelized only scoring. The current implementation instead maps an
integer route index to one candidate with \texttt{route\_from\_index()}.
Each worker constructs and scores its assigned candidates immediately, so
candidate generation is also parallel and the full route vector is no longer
stored. The exact candidate count is available without constructing routes:
for non-collinear endpoints it is
\[
N_{\mathrm{routes}} = d_x + d_y + 2(d_x-1)(d_y-1),
\]
where $d_x$ and $d_y$ are absolute endpoint differences. Collinear endpoints
have one candidate. This preserves a route-count-based sequential fallback.

Each thread maintains a private best route and cost. At the end of the parallel
search, the main thread combines the per-thread results. This is a manual
minimum reduction, analogous to accumulating partial sums independently and
combining them once, rather than synchronizing after every candidate.

\paragraph{Fine granularity.}
In \texttt{schedule(static, 1)}, a chunk is one candidate route, not one cell.
Candidates are assigned round-robin without a dynamic task queue. A candidate
still performs a complete path evaluation, so a small chunk does not imply
that each scheduled unit contains only a trivial amount of work.

Importantly, all generated candidates for a particular wire have the same
Manhattan length, $d_x+d_y$, and visit the same number of cells.
Path lengths vary between wires, but the W-mode parallel loop processes only
one wire's candidates at a time. Therefore, the chunk-one result cannot be
explained by balancing different wire lengths. Candidate orientations, bend
counts, and memory access patterns can differ even with equal path length;
a fine cyclic assignment may distribute those differences, but these effects
were not separately measured. The timing data justify choosing chunk one
provisionally, not a general claim that finer granularity is always better.

The parallel threshold is the multiplier times the thread count: the tested
values correspond to 16, 32, 64, 128, and 256 candidates at eight threads.
We retained multiplier four; the corrected medians for 4, 8, and 16 differed
by only about 0.2\%. The sequential fallback avoids entering a parallel region
for very small searches, but this sweep does not establish an exact optimal
cutoff or how frequently each threshold changes the execution path.

Our selected configuration is therefore static scheduling, chunk size one,
and threshold multiplier four. These decisions are based on medium-input
measurements and must still be checked on few and abundant inputs and in
the final scaling evaluation.

\subsection{Synchronization and Shared Memory}

Threads share both occupancy views, but only read them during candidate scoring,
so no occupancy locks are needed in W mode. Multiple threads reading the same
cache line do not cause write-induced coherence invalidations and may benefit
from shared cache reuse. This is distinct from false sharing, which requires
writes to a shared cache line; our local bests remain private throughout scoring.
Actual cache benefits depend on working-set size and scheduling and have not
yet been quantified with cache-miss measurements.

The worksharing loop has an implicit barrier. Each worker then publishes its
local best to its own result slot, and the parallel-region end synchronizes
completion before the main thread reduces those results. Occupancy removal
and insertion remain sequential, outside the parallel region. Thus no critical
section or atomic update is needed for each candidate comparison.

We moved the per-thread result-vector allocations outside the iteration and
wire loops, reusing storage across searches. Before each parallel search,
cost slots reset to the current wire's starting best; active threads overwrite
their route slots. Unused slots cannot select stale routes because the final
reduction accepts only strictly cheaper costs. Buffer reuse showed no
measurable computation-time improvement, so we retain it as a simple allocation
cleanup rather than attributing a speedup to it.

Equal-cost route choices can differ across thread counts and schedules because
the reduction does not impose a deterministic candidate-index tie-break.
Those choices can affect later wires and explain different final costs without
an occupancy mismatch. Consequently, some tuning runs follow different routing
trajectories rather than exactly identical work.

\section{Across-Wires Parallelism}

Our initial A-mode baseline assigns batches of wires to workers using dynamic
scheduling. Each worker explores its batch's wires sequentially, remembers all
chosen routes, and only then commits the batch's removals and insertions.
One parallel region spans all iterations, with a barrier between iterations.
Workers have private random generators and reusable batch-route storage.

Unlike W mode, A cannot remove a wire before its batch finishes selecting
routes. The initial scorer therefore read each cell atomically and subtracted
one when \texttt{cell\_on\_wire()} found that cell on the current route:
$(value-onOldRoute+1)^2$. That helper scanned up to four old segments for
every cell of every candidate. Atomic increment/decrement updates protect both
occupancy views; atomic reads permit concurrent scoring without a C++ data race.
They do not provide a consistent whole-route snapshot, which the assignment
does not require.

\subsection{Isolating the Initial Scoring Overhead}

The first reported one-thread few-input A computation time was approximately
15 seconds, compared with W's 2.82 seconds on the same input. This was an
exploratory symptom rather than a controlled median-of-three benchmark.
Because the discrepancy occurred at one thread, cross-worker update contention
and work imbalance could not explain it. Extracting the mode implementations
into separate functions improved organization but did not remove the per-cell
membership checks; we therefore investigated the scoring loop before tuning
scheduling or batch size.

\subsection{Moving Geometric Checks Out of the Cell Loop}

We now determine overlaps between each candidate segment and the old wire
before visiting that segment's cells. Parallel segments yield overlap intervals;
perpendicular crossings yield single-cell intervals. These ranges are clipped
to the candidate's half-open traversal bounds, sorted, and merged so shared
bends are not subtracted twice.

The scorer then walks non-overlapping spans using $(value+1)^2$ and overlapping
spans using $value^2$, where removing the old wire and adding the candidate
cancel. This replaces a segment scan at every cell with a small fixed-size
range calculation per segment. Every cell is still read atomically and
evaluated once, and the final endpoint is included separately.
Only geometric overlap metadata is computed: there are no cached costs,
prefix sums, skipped candidates, or early termination.

The updated scorer's local median was 0.428 seconds versus 1.63 seconds
for the initial A scorer, approximately a $3.80\times$ scoring-only improvement
across the two measurement sets. This is encouraging but not a prediction of
the full-program speedup. Cost-reference tests, before/after output comparisons,
and atomic-update stress checks passed; a matching GHC before/after benchmark
and full OpenMP validation remain to be collected. Batch selection/update timing,
random selection, scheduling, and W mode are unchanged.

\section{Optimization Hypotheses}

The main performance themes we plan to evaluate are workload balance,
scheduling overhead, locality, and contention.  Within-wires parallelism exposes
candidate routes as independent tasks; this should work best for wires with large
bounding boxes and many possible routes.  Across-wires parallelism exposes wires
or batches of wires as tasks; this may require dynamic scheduling or
longest-task-first ordering to avoid stragglers.

We will also consider locality-aware across-wires batching as a later experiment.
For example, wires could be grouped by bounding-box midpoint or quadrant so that
threads tend to work on nearby occupancy cells.  This may improve cache locality,
but it may also increase contention because nearby wires are more likely to
overlap.  We will only pursue this direction if cache miss or synchronization
measurements suggest that the extra work is justified.

\section{Final Implementation Decisions and PSC Evaluation}
\label{sec:final-decisions}

This section records the final implementation used for the completed PSC
benchmark set. It is intentionally detailed so that the design can be audited
against the assignment rules and so that individual optimizations can be
separated from algorithmic changes. The benchmark source commit was
\texttt{70c112e}; later experiments with a single-thread A-mode fast path and
guided A-mode scheduling were reverted because neither provided a robust final
improvement. Thus the final routing code matches the code used for the PSC
measurements below.

\subsection{Final decisions, rationale, and synchronization}

\paragraph{Exhaustive route set and direct construction.}
For every greedy reroute, both modes enumerate the complete assignment-defined
set of legal routes with at most three bends. We do not sample a subset, cache
route costs, use prefix sums, or terminate a score early. The optimization is
only representational: the old implementation materialized all candidate
\texttt{Wire} objects in a vector, while the final implementation maps a route
index directly to its keypoints and immediately scores it. This reduces
allocation and temporary storage traffic without changing the route set or the
score of any candidate. In W mode the route index is the unit of parallel work;
in A mode one worker generates and scores routes serially for each wire in its
assigned batch.

\paragraph{Two occupancy views for spatial locality.}
The row-major matrix \texttt{occupancy[y][x]} makes a horizontal segment scan
contiguous. A transposed matrix \texttt{occupancy\_columns[x][y]} makes the
corresponding vertical scan contiguous. Every route insertion/removal updates
both views, so they represent identical logical occupancy. This deliberately
trades a small amount of write work and memory for locality in the dominant
operation: the many full candidate-score scans. It is not a range-query data
structure; every candidate still reads every one of its cells. The decision was
motivated by profiling and the observation that the scorer dominated runtime,
while the transpose makes the vertical case match the horizontal case's
unit-stride access pattern.

\paragraph{W-mode parallel candidate search.}
Within-wires parallelism preserves the original dependency order across wires:
the program removes one wire, evaluates all of that wire's candidates in
parallel against a read-only occupancy state, selects one best route, commits
it, and only then advances to the next wire. The per-wire candidate loop uses
\texttt{schedule(static,1)}. Each worker retains a private best route/cost,
then the thread that resumes after the parallel region performs a reduction.
The implicit barrier at the end of the worksharing loop and the end of the
parallel region guarantee that every local best is complete before the reduction
and subsequent occupancy update. Occupancy updates are therefore sequential in
W mode; no atomic operations or locks are required during scoring.

Static scheduling, chunk size one, and a candidate-count threshold of four
times the requested thread count were selected from medium-input GHC sweeps.
The threshold keeps small searches sequential, avoiding the cost of forming a
parallel team when there is too little candidate work to amortize it. Static
chunk-one scheduling was slightly faster than dynamic scheduling in the sweep;
the differences were modest, so we describe this as a measured configuration
choice rather than a general scheduling law. The PSC curves later show the
expected limit of this approach: there is only one wire's candidate set
available at a time, so high core counts can run out of useful work or pay
disproportionately for barriers and reductions.

\paragraph{A-mode batch selection and atomic commit.}
Across-wires parallelism exposes batches of wires as the independent units.
One OpenMP parallel region spans all simulated-annealing iterations. In each
iteration, \texttt{schedule(dynamic,1)} assigns a batch to an available worker.
The worker scores every wire in the batch, keeps route changes in a private
\texttt{RouteUpdate} vector, and commits its changes only after all wires in
that batch have chosen their routes. Each commit atomically decrements the old
route and atomically increments the new route in both occupancy views. Atomic
loads are used while scoring, so an overlapping commit cannot create a C++ data
race with a reader. The implicit barrier at the end of the \texttt{omp for}
ensures every commit in an iteration has finished before the next iteration
begins.

This design deliberately permits the staleness specified by the assignment:
a candidate may have been scored before another batch commits. It introduces no
additional staleness beyond the chosen batch structure, and it preserves the
final occupancy invariant because every changed route is removed and inserted
exactly once. The validator checks this invariant after every benchmark run.
Dynamic one-batch scheduling was retained because wires have heterogeneous
bounding boxes and hence heterogeneous candidate counts. A guided-scheduling
experiment on GHC gave a medium-input eight-thread median of 1.283~s versus an
earlier dynamic median of 1.290~s, a difference too small to distinguish from
run-to-run variation; abundant-input guided trials were also noisy. The
experiment was reverted rather than treating a sub-percent difference as a
reliable optimization.

\paragraph{A-mode old-route overlap metadata.}
Leaving the old wire in A-mode occupancy makes naive scoring expensive if every
candidate cell asks whether it lies on the old route. The final scorer first
normalizes the old wire into at most four segments. For each candidate segment,
it computes a constant-size list of parallel overlaps and perpendicular
crossings, clips those intervals to the candidate, sorts and merges them, then
walks each cell exactly once. This moves geometric membership checks out of the
inner cell loop. It does not omit route cells or reuse scores. A scoring-only
diagnostic reduced the original atomic-plus-membership-check case from 1.63~s
to 0.428~s on the measured local workload, motivating this optimization. Later
GHC profiles still attributed approximately 97\% of A-mode cycles to the final
candidate-score function, so score computation remains the appropriate
explanation for the remaining A-mode cost rather than OpenMP scheduling.

\paragraph{Rejected single-thread A fast path.}
We temporarily removed A-mode atomic occupancy operations when only one thread
was requested. It preserved validation and output cost, but changed aggregate
cycles by only about 1.5\% in a GHC \texttt{perf stat} comparison. The added
code complexity was not justified, so the experiment was reverted. This result
also indicates that the remaining serial A-mode gap is not primarily an
uncontended atomic-operation problem.

\subsection{PSC methodology}

We ran a single complete experiment set on a dedicated Bridges-2 Regular
Memory node, not a shared or login node. The Slurm job rebuilt the program with
\texttt{make -B} on the allocated node and used \texttt{OMP\_PLACES=cores} and
\texttt{OMP\_PROC\_BIND=close}. It measured all three timing inputs, both
parallel modes, and 1, 2, 4, 8, 16, 32, 64, and 128 threads. Each configuration
used $P=0.1$, five annealing iterations, and $B=1$, and was repeated three
times. The complete matrix contains three inputs, two modes, eight thread
counts, and three trials, for 144 runs. All 144 runs printed
\texttt{Validate Passed: no mismatches.} The raw trials,
per-trial total times, and derived medians are preserved in
\texttt{PSC\_BENCHMARK\_48936839\_RAW.csv} and
\texttt{PSC\_BENCHMARK\_48936839\_SUMMARY.csv}.

For each input/mode/thread-count point, we report the median of three trials.
Computation time is the router's reported computation interval. Total time for
one trial is initialization plus computation, and total-speedup uses the median
of those per-trial totals. This is preferable to adding independently rounded
medians. Each speedup uses the corresponding one-thread result for the same
input and mode:
\[
S_p^{\mathrm{compute}}=\frac{C_1}{C_p},\qquad
S_p^{\mathrm{total}}=\frac{T_1}{T_p}.
\]

\subsection{Interpretation and comparison with the reference}

At eight threads, both modes scale well for every input: W obtains computation
speedups of $7.81\times$, $7.30\times$, and $6.43\times$ for few, medium, and
abundant inputs, while A obtains $8.45\times$, $8.56\times$, and
$8.47\times$. The slight superlinear values for A at eight threads should not
be treated as evidence that more than eight cores of work occurred; they are
consistent with normal run-to-run variation and cache/work-distribution effects
relative to the selected one-thread median.

The two strategies diverge at high core counts. W peaks at 64 threads on few
and medium, and at 32 threads on abundant, before flattening or regressing.
For medium and abundant inputs, candidate searches for individual wires cannot
always supply enough balanced work to amortize repeated parallel-region and
barrier costs. The abundant W-mode 128-thread trials also had larger variation
than the rest of the PSC dataset, so the 128-thread median should be reported
with caution rather than over-interpreted.

A-mode instead reaches $96.36\times$ computation speedup on medium and
$107.60\times$ on abundant at 128 threads. These results are consistent with
A-mode's larger pool of concurrently selectable wires. Few-input A-mode levels
off around 32 threads because only 128 wires are available and the fixed
initialization cost becomes a larger fraction of total time. The total-speedup
table makes that serial-initialization effect explicit: for example, medium
A-mode falls from $96.36\times$ computation speedup to $86.72\times$ total
speedup at 128 threads.

Table~\ref{tab:reference-one-thread} compares our PSC one-thread computation
medians with the handout's good-performance reference. W-mode is close to the
reference on few and medium and is slower on abundant. A-mode's one-thread
time is higher than the reference, even though its high-core-count scaling is
strong. Speedup therefore must be read together with absolute computation time:
a slower one-thread baseline can inflate a relative speedup. This is one reason
we report both tables and preserve the raw measurements.

\subsection{Comparison with GHC}

At eight workers, GHC W-mode speedups are $7.70\times$, $7.20\times$, and
$5.95\times$ for few, medium, and abundant inputs, compared with PSC values of
$7.81\times$, $7.30\times$, and $6.43\times$. The same qualitative limit is
visible on both systems: within-wires exposes candidates of only one wire at a
time, so increasingly large teams eventually encounter insufficient work,
barriers, and shared-occupancy traffic. PSC retains a modest advantage for
abundant W at eight threads, but neither platform makes W ideal at large
machine sizes.

For A mode, GHC eight-worker speedups are $7.35\times$, $6.88\times$, and
$6.40\times$, whereas PSC reports $8.45\times$, $8.56\times$, and
$8.47\times$. PSC's lower one-thread A performance makes its relative speedup
somewhat more favorable, so this comparison is not solely a property of the
parallel schedule. Still, the PSC 128-thread curves demonstrate the key
algorithmic difference: multiple selectable wires keep far more independent
work available than W mode, especially on medium and abundant inputs. We
therefore use GHC to study cache and eight-worker behavior and PSC to expose
the high-core-count scalability limit.

\subsection{A-mode sensitivity studies and output}

The required A-mode probability sweep on medium input was stable: computation
speedup at eight threads was $7.39\times$ for $P=0.01$, $7.40\times$ for
$P=0.1$, and $7.39\times$ for $P=0.5$. Higher $P$ reduces absolute work
(median one-thread computation times 10.697, 9.750, and 5.504 seconds), but
does not materially change parallel efficiency.

For the problem-size studies, eight-thread A-mode speedups were $7.20\times$,
$6.39\times$, and $7.36\times$ for grid dimensions 512, 2048, and 8192.
With 256, 1024, and 4096 wires on the 2048 grid, they were $7.39\times$,
$7.27\times$, and $6.38\times$, respectively. Thus A mode generally has
enough independent wire work to scale well at eight workers; the largest
wire-count case shows the expected loss from greater occupancy interference.
